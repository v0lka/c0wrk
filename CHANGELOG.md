# Changelog

All notable changes to **c0wrk**. Dates follow the tag date.

## v0.11.0 — 2026-10-06

### Added
- **Session-bound managed git worktrees** ([#131](https://github.com/v0lka/c0wrk/pull/131)) — implements [ADR-080](./specs/decisions/080-session-worktrees.md). A session's execution workspace becomes an explicit, persisted, per-session notion instead of the implicit path derived from the active checkout at creation: a typed, immutable binding (`local` | `managed_worktree`) is persisted in `sessions.workspace_binding` (migration, derived-path validation, one-session-per-tree unique index), core worktree primitives (list/add/recreate/remove/prune) run with per-repo serialization, fail-closed porcelain parsing, an explicit failure taxonomy, `info/exclude` container exclusion and the invariant that branches are never deleted, and a `backend/worktrees.Owner` coordinator wires the session lifecycle — `CreateManagedSession` (draft → provision → commit → persist, compensated on failure), a restore-time ensurer that recreates a missing tree from its pinned branch with a data-loss warning, managed forks at the source's committed HEAD, and a dirty/locked-aware deletion protocol (`SessionDeleteBlockedError`). The Git panel gains a focus model behind every git RPC, a worktree list with owning-session metadata and pinned-branch refusal, plus `GitFocusButton`/`WorktreesSection`; a managed-worktree traversal gate keeps local sessions out of sibling session trees, and git monitoring, status, diff and the vector index become worktree-aware. Frontend: New Session arms a draft the toolbar's `SessionWorkspaceSelector`/`BranchPicker` use to pick the branch, and the first send/attachment/terminal open commits it. See [session-worktrees.md](./specs/domains/session-worktrees.md).
- **Per-root vector index registry** ([#131](https://github.com/v0lka/c0wrk/pull/131)) — implements [ADR-081](./specs/decisions/081-vector-per-root-registry.md). The process-wide singleton index — whose single active target was re-pointed on every send and project switch — is replaced by one `vectorindex.Manager` per workspace root, owned by a backend registry (`backend/vector_roots.go`). Agent-side `semantic_search`/RAG resolves the root from the executor context (a session always searches its own tree) while user-facing RPCs resolve the Git-panel focus root; manager creation is single-flight per root under an LRU-bounded live set with the focus pinned, per-root embedding caches are siblings of the project cache (never nested), and `ShutdownAll` closes every live manager before releasing the process-global embedder exactly once. The send-time re-scope is deleted.
- **Unified `/-ref` kind colors** ([#131](https://github.com/v0lka/c0wrk/pull/131)) — a single kind→color mapping is shared by the chat chips, the editor decorations and the autocomplete list: subagents use highlight, MCP servers use info and skills use success (skill chips previously rendered as a plain boxed chip; a plain `/name` now defaults to the skill tint). The reference highlighter rides the same slash-ref grammar as the send and display paths, so qualified refs keep their explicit kind, and the autocomplete section headers mirror the kind colors.
- **ChatGPT subscription (OAuth) sign-in** ([#120](https://github.com/v0lka/c0wrk/pull/120), closes [#100](https://github.com/v0lka/c0wrk/issues/100)) — implements [ADR-074](./specs/decisions/074-chatgpt-subscription-auth.md). A second authentication mode alongside API keys: a browser OAuth flow with PKCE and refresh credentials in the OS keychain, integrated with the session routers and the streaming-only Codex backend and never silently falling back to API-key auth. Settings gain sign-in/cancel/sign-out/account-status controls and a live subscription model catalog with an offline preset fallback, and credential restoration, refresh concurrency, cancellation, duplicate callbacks, busy callback ports, and proxy routing are hardened.
- **Unified slash mentions** ([#128](https://github.com/v0lka/c0wrk/pull/128), closes [#110](https://github.com/v0lka/c0wrk/issues/110)) — implements [ADR-076](./specs/decisions/076-unified-slash-mentions.md). Capability selection moves to a single `/` completion list ordered **Subagents → MCP Servers → Skills**, replacing the hash-based subagent trigger so `@file#L20` line anchors can never collide. Plain mentions and collision-qualified `/agent: <id>` / `/mcp: <id>` / `/skill: <id>` forms (spaced or unspaced) are supported, an ambiguous plain `/name` is preserved as text with a hint instead of silently activating, and parsing, autocomplete, message chips, preprocessing and send-path threading are updated with `/goal` behavior preserved.
- **MCP server activation modes** ([#128](https://github.com/v0lka/c0wrk/pull/128), closes [#111](https://github.com/v0lka/c0wrk/issues/111)) — implements [ADR-077](./specs/decisions/077-explicit-mcp-server-mentions.md). Per-server `auto` | `manual` | `disabled` modes: `auto` (default) advertises as before, `manual` keeps the server connected but exposes its tools only after an explicit `/`-mention, and `disabled` is never dialed. Manual activation is task-wide — mentions union as durable task-owned names (`task_mcp_mentions`) surviving continuation, pause/resume, restart and independent session forks — and the allowed set `auto ∪ (manual ∩ mentioned)` is enforced as a gated complement across the orchestrator's descriptor filter, the delegation launcher, E2S and the registry dispatch gate (fail-closed, the error naming the server), with a soft **Requested MCP Servers** prompt section that nudges without overriding `disabled`. The mode controls live on the server cards beside Edit/Delete with per-mode explanations and concurrent-save guards ([8b4e8709](https://github.com/v0lka/c0wrk/commit/8b4e8709)).
- **Single-instance lock** ([#127](https://github.com/v0lka/c0wrk/pull/127), issue [#98](https://github.com/v0lka/c0wrk/issues/98)) — implements [ADR-075](./specs/decisions/075-single-instance-lock.md). Wails' `SingleInstanceLock` makes a LaunchServices-spawned second process (a stale-bundle notification click, a Finder re-open) exit before creating a window or opening the database, while the first instance focuses its window through the shared show-window funnel. An app-level advisory lock (`~/.c0wrk/app.lock`, `flock`/`LockFileEx`, fail-open on setup errors) is acquired before `crashlog.Install` so a transient relay process never stashes or orphans the running instance's liveness marker.
- **Collapsible turn-work containers** ([#126](https://github.com/v0lka/c0wrk/pull/126)) — each chat turn's work (thoughts, tool cards, intermediate assistant texts, service markers) is wrapped in collapsible `TurnWorkBlock` containers so settled history reads as a few one-line rows per turn while the live turn stays open. The pure `splitTurnWork` segments the last sticky turn into `{work, tail}` anchored on the last assistant item, open state derives from `taskActive` (live → open, settled → collapsed, including dead turns that render an interrupted block after a reload), unresolved pending-action panels (`tool_confirm`, `ask_user`, `step_limit`, `plan_review`, `goal_proposal`, `resume_action`) are lifted into the tail so they stay reachable, and top-level `plan_step`/`subagent` blocks with their `execute_plan`/`delegate` launcher cards pin between block and tail — cutting the work region into ordered segments in stream order, with delegated plans nesting inside their `SubAgentBlock`. Bookmark/plan-step navigation expands the owning block first, and `groupMessages` sinks open step/subagent blocks to the bottom so the active step renders below the nudge that resumed the run. See [rendering.md](./specs/domains/frontend/rendering.md).
- **Font system: user font selection, per-scope smoothing, and a tokenized type scale** ([#130](https://github.com/v0lka/c0wrk/pull/130)) — the type scale and font-family stacks become `@theme` tokens guarded by source scans. Chosen UI (sans) and monospace families replace the boolean follow-system-font toggle ([ADR-078](./specs/decisions/078-user-font-selection.md)): build-tagged probes read GNOME's interface/monospace fonts (`gsettings`) and enumerate installed families (`fc-list`), a `fontStore` persists both and applies them pre-paint, free-text `StringCombobox` pickers offer Default/detected/current/installed families, the legacy `c0wrk-follow-system-font` key is retired, and the terminal and CodeMirror read the live CSS vars. Independent `-webkit-font-smoothing` knobs for the UI and mono scopes land via `fontStore` v2 ([ADR-079](./specs/decisions/079-font-smoothing-selection.md)). Arbitrary `text-[Npx]` utilities become named scale classes under a `typeScaleInvariant` guard, the chat autocomplete tooltip is pulled back into the UI font chain (contested rules move from global CSS into `createChatEditorTheme`), and font families are canonicalized at the apply boundary. See [fonts.md](./specs/domains/fonts.md).
- **Opt-in "follow desktop UI font"** ([#124](https://github.com/v0lka/c0wrk/pull/124)) — reads the GNOME interface font via `gsettings` (`GetSystemUIFont`) and applies the family as the inline `--default-font-family` override on `<html>` when the user opts in; non-GNOME desktops and other platforms report "unavailable" and the setting stays hidden.
- **Shared `SegmentedControl`, single-channel button tooltips, and name-first git rows** ([#125](https://github.com/v0lka/c0wrk/pull/125)) — one chrome for every segmented surface (tabs semantics with a roving tabindex for view switches, radio semantics for option picks; the chat input mode, settings tabs and review view mode migrate to it); every button exposes its purpose via exactly one channel — a native `title`, a Radix `TooltipTrigger`, or a statically visible label, never combined — enforced by a project-wide `buttonTitleInvariant` AST guard plus a scoped chat guard, with a disabled-row pattern keeping the blocked reason in the a11y tree; the Changes tab leads rows with the file name (directory as secondary) and tree rows render basename-only with full-path tooltips; and the research pickers rework timing waits into deterministic lifecycle proofs. See [button-tooltips.md](./specs/domains/frontend/button-tooltips.md).
- **Bonsai model profile, checkpoint tuning knobs, and a derived prompt-cache ceiling** ([#123](https://github.com/v0lka/c0wrk/pull/123)) — a predefined `bonsai.2-27b` Model Profile tuned for the embedded model's measured prefill/token cost (the embedded suggestion alias retargeted to it); new `ctx_checkpoints`/`cache_idle_slots` planner knobs rendered explicitly on every launch so inherited `LLAMA_ARG_*` env values cannot decide memory-bearing settings; an unset `cache_ram_mib` derives the prompt-cache limit from measured spare memory, raising it above the runtime's 8192 MiB default only; `reasoning_content` history echo is disabled for the embedded provider (the supervised llama.cpp chat template rejects it); and an advisory `BonsaiProfileBanner` nudges toward the profile when the embedded model runs under a different one (hint only, never auto-applied). See [model-profiles.md](./specs/domains/model-profiles.md).
- **Embedded LLM: userland-aware guard substitution, universal smoke test, and scoped removal** ([#116](https://github.com/v0lka/c0wrk/pull/116)) — implements [ADR-073](./specs/decisions/073-userland-aware-guard-substitution.md). The `cuda-13.3-crash` guard (`PrismML-Eng/llama.cpp#222`) no longer substitutes `cuda-12.8` blindly: the CUDA 12.x userland (`libcudart.so.12`/`libcublas.so.12`) is probed first — including the `.so.12`-symlinked-to-13-series packaging trap — and a withheld substitution is recorded as an honest guard record instead of a silent swap. The `llama-server --version` smoke test leaves the darwin-only branch and runs on every platform before the weights download, so a Linux install with missing CUDA runtime libraries fails in seconds with an actionable diagnosis instead of after a multi-gigabyte fetch. **Remove becomes a split button** (full / runtime-only / weights-only / vision-projector-only): every scope stops the server first and clears the manifest and the generated `embedded` provider, so a partial removal leaves a verified cache and a reinstall re-verifies surviving bytes; leftover flags disable items whose bytes are absent and surface a cleanup row on a not-installed machine; and the previously backend-only guard record now renders in the UI (warning + remedy sentence + upstream issue link) with a wire-shape fix so guard substitutes always serialize. See [embedded-llm.md](./specs/domains/embedded-llm.md).
- **Silent-mode `user_confirm` sub-policy** ([#114](https://github.com/v0lka/c0wrk/pull/114)) — implements [ADR-072](./specs/decisions/072-silent-mode-user-confirm-policy.md). A fourth `security.silent_mode` sub-policy (`confirm` | `deny` | `escalate`, default `deny`) refines only the fail-closed CONFIRM outcome of the tool-confirm judge terminal — a spoken CONFIRM, or a missing/failing/timed-out/unparseable judge: `deny` keeps the existing auto-denial, `escalate` restores the blocking confirmation card, and `confirm` executes the call unattended (canonical hard reasons included), audited as an allow with policy `user_confirm`. The refinement never governs a deliberate DENY or an ALLOW and sits below the interactive canonical backstop, so `confirm` is unsafe opt-in twice over (the silent posture plus the value, gated in Settings behind a danger modal). The judge memo is no longer keyed on spoken CONFIRMs (only a DENY memoizes), and the value participates in the per-task tightening check.
- **Per-service-kind telemetry for the one-shot service calls** ([#117](https://github.com/v0lka/c0wrk/pull/117), issue [#64](https://github.com/v0lka/c0wrk/issues/64)) — the auxiliary one-shot calls (session title, commit message, prompt-optimizer extract/rewrite, compaction summarization) now share one instrumented entry, `core/service_call.go: serviceCall`, which wraps the sp4rk `oneshot` client with the telemetry the client cannot own: per-kind counters/latency (`core/service_metrics.go: ServiceMetrics` — calls, attempts/retries, `ok`/`fallback`/`error`/`transport_error`, and summed/slowest duration; read via `OrchestratorBuilder.ServiceMetricsSnapshot()` — a Go-level read-API; it has no production reader yet, exposing the snapshot as an RPC lands as a separate change — and shared into every per-session orchestrator so manual compaction records alongside the rest) and exactly one unified structured log record per call (`service_kind`/`model`/`outcome`/`attempts`/`duration`), emitted by c0wrk alone so the field set cannot drift between helpers and the client and c0wrk never log the same record twice (domain-level diagnostics at the call sites — the commit-message validation warning, the per-attempt rewrite warnings — are separate records by design). Every degraded outcome logs at Warn — including the optimize-extract fallback, a normal by-design outcome that returns the original prompt after the nudge loop; a deliberate spec decision, to be revisited only if release telemetry shows it is regular noise. The manual-compaction caller that previously passed no logger now emits the unified record too. See [llm-providers.md](./specs/domains/llm-providers.md#service-call-observability).
- **Windows PowerShell build script and docs** ([57993252](https://github.com/v0lka/c0wrk/commit/57993252)) — `build.ps1` as a one-to-one PowerShell analog of the Makefile (`build`/`test`/`lint`/asset-fetch plus a `ps-check` parse-check target), a repo-wide `.gitattributes` forcing LF (so CRLF checkouts cannot break `gofmt`), the Wails Windows packaging scaffolding ignored, and CONTRIBUTING.md build prerequisites with refreshed pinned toolchains (Go 1.27.1, Node 24, Wails v2.15.0, golangci-lint v2.13.2, govulncheck v1.7.0).
- **Mention description pane in the chat autocomplete** ([f886ef20](https://github.com/v0lka/c0wrk/commit/f886ef20)) — the full description of a hovered `/-mention` row (subagents, MCP servers, skills) renders as sanitized markdown in a body-level pane mirroring the chat tooltip chrome, anchored to the pointer and flipping when there is no room above (zoom-safe via visual→layout px conversion); both completion lists open upward with aligned popup chrome (shared elevation, custom scrollbar, pointer-hover tint).

### Fixed
- **Embedded LLM: the `nvidia-smi` probe accepts the CUDA UMD Version column** ([#115](https://github.com/v0lka/c0wrk/pull/115)) — NVIDIA renamed the header column from "CUDA Version" to "CUDA UMD Version" in the 610.x drivers, so the probe regex no longer matched and CUDA-capable hosts silently fell through to the Vulkan rung (PTQ1_0 packing). Both spellings now match, and a Debug excerpt of the probe output is logged when `nvidia-smi` answers without a usable version, so a future rename is distinguishable from a non-CUDA machine.
- **Continuation resume keeps replayed plan steps silent** ([#119](https://github.com/v0lka/c0wrk/pull/119), fixes [#99](https://github.com/v0lka/c0wrk/issues/99)) — resuming a failed/interrupted task re-emitted synthesized `PlanStepStart` + `PlanStepComplete(success)` pairs for every already-successful step, producing duplicate retry-badged plan blocks that persisted in history after an app restart (a same-process resume masked the bug). `inlineStepLifecycle.seedCompletedFromBlackboard` now silently marks every step with an error-free blackboard `StepResult` as completed, and a synthesized success pair is emitted only when the plan was (re-)declared **in this run** via `declare_plan`; a continuation resume settles skipped steps silently. See [session-lifecycle.md](./specs/domains/session-lifecycle.md).
- **Namespaced tool-not-found diagnostics with catalog-scoped hints** ([#122](https://github.com/v0lka/c0wrk/pull/122)) — a failed tool lookup now returns an actionable `sdktools.ToolNotFoundResult`: when the name carries an OpenAI-style `functions.` prefix and the unqualified candidate is registered, enabled and inside the effective run-scoped catalog, the error suggests the exact name to use. The hint respects the catalog scope injected by delegation (a candidate outside it is never recommended), never dispatches the candidate and never triggers a confirmation; an exactly-registered `functions.x` still wins, and missing/disabled/filtered candidates fall back to the generic error.
- **Chat collapse re-anchors the viewport** ([#129](https://github.com/v0lka/c0wrk/pull/129)) — collapsing a block the user was reading no longer parks the viewport on whatever followed (often nothing, leaving an apparently empty chat): `CollapsibleBlock` anchors back onto the block start on an open→closed transition when its header ends above the fold and is the single scroll writer for collapses, while an at-bottom gate (`ScrollContext.getIsAtBottom`/`setIsAtBottom`) skips the reposition when following the live tail. Also wires `WorkspacePanel` through the ARIA tabs pattern and consolidates `BaseSelectorRow`'s tooltip/title handling into a single `typeMeta` record.
- **`serviceCall` guards against a nil caller** ([#117](https://github.com/v0lka/c0wrk/pull/117)) — a nil logger/caller no longer panics the instrumented one-shot entry.
- **Model Profiles: the embedded preset is renamed to a dotted id** ([#123](https://github.com/v0lka/c0wrk/pull/123)) — the predefined embedded profile becomes `bonsai.2-27b` so a custom "Bonsai 2 27B" profile (id `bonsai-2-27b`, derivable by the custom slug generator) survives catalog growth on upgrade instead of being dropped and blocking the store writer; a stored dashed `active_profile` resolves through `legacyPredefinedModelProfileAliases` with one warning, consulted only after a direct catalog lookup fails so it can never hijack a custom id.
- **Research multi-file writes are all-or-nothing** ([#123](https://github.com/v0lka/c0wrk/pull/123)) — a research artifact write spanning several files now rolls back on failure instead of leaving a partial set.
- **Embedded LLM: `ldconfig -p` cache paths are CR-stripped** ([#116](https://github.com/v0lka/c0wrk/pull/116)) — a CRLF-emitting `ldconfig` no longer downgrades a working CUDA 12 userland to `unknown`, and the runtime smoke test runs under the real launch environment.

### Internal
- **Dependency bumps** — `github.com/v0lka/sp4rk` is bumped through the cycle to `v0.15.1-0.20261006173855-3591ba7ba2f2` ([#133](https://github.com/v0lka/c0wrk/pull/133) et al.) for the safeio regular-file guard, `ToolNotFoundResult`/`WithCatalogScope`, and the subscription-auth/`timeout_class` support the features above consume.

## v0.10.1 — 2026-09-29

### Added
- **Adaptive per-model LLM request budgets** ([#112](https://github.com/v0lka/c0wrk/pull/112)) — implements [ADR-071](./specs/decisions/071-adaptive-llm-request-budgets.md). The main-agent request deadline is now learned per model from live traffic instead of one fixed 600 s. The new `core/llmbudget` package keeps a session-scoped, in-memory ring of the last 32 timed samples per model (fed by the sp4rk timed-usage observer — successful calls only, never synthetic probes), fits `duration ≈ in·r_in + out·r_out` priced at the p85 tail, and clamps the result into a per-class envelope with compile-time-exported floors and ceilings (`remote` 120–600 s, `local` 300–1800 s, `embedded` 600–1800 s — the ADR-067 `limits.go` precedent), degrading through a size-normalized percentile down to the class constants when the fit is degenerate. A transport arms the resolved budget as a context deadline on the provider wire and escalates it ×2 when its own expiry killed the request (re-clamped at the class ceiling, cleared by the next successful call); until a model has 3 samples every request runs under a conservative 600 s warmup. `timeouts.llmRequestTimeout` becomes tri-state: `0` (the new shipped default) means "no opinion" and the adaptive budget governs, a positive value stays a fixed override that is never escalated, and the kill-switch `timeouts.adaptive_budget.enabled` (default on) restores the fixed regime byte-for-byte — where `0` keeps its legacy 600 s meaning. New knobs: per-provider `timeout_class` (`local` | `remote`; inferred from a loopback `base_url` when omitted, and rejected — as any invalid enum — on the reserved `embedded` provider through one shared `ValidateProviderTimeoutClass` gate at load and at the `UpdateLLMConfig` trust boundary) and per-model `llm.models.<name>.request_timeout` (0–3600 s, fixed, senior to every other rule, preserved through `SetModelConfig`). Each ingested sample measures the single winning provider attempt — via an `AttemptRecorder` context side-channel, not the whole router call — so the router's retry backoff cannot inflate the fitted rates; the budget transport is installed between the TLS pin and the embedded ensure-loaded gate, so a cold model load stays outside every deadline, and one-shot service calls keep their fixed `serviceLLMRequestTimeout` path.

### Fixed
- **Goal mode: pause → resume no longer collapses an unfinished goal** ([#94](https://github.com/v0lka/c0wrk/issues/94), fixed by [#113](https://github.com/v0lka/c0wrk/pull/113)) — a resumed run that ended its first turn without a tool call or verdict was classified `blocked_idle` and surfaced as a **failed** session ("Goal blocked" badge + `task_failed_resumable` banner), even with turn budget remaining. Resume now CONTINUES the interrupted turn (the `runGoalTurns` first resumed turn re-uses `GoalState.TurnCount` — no extra budgeted turn burned per pause/resume cycle) and tolerates an idle first resumed turn (the loop continues instead of halting). A `blocked_idle` halt is now mapped by `goalLoopResult` to `ExecutionStatusPaused` — a resumable **suspension** (paused session, "Goal blocked" badge, Resume available) rather than a failed session. See [goal-mode.md](./specs/domains/goal-mode.md#resume-continuity).
- **Goal mode: resume entry points keep the goal pursuit** ([#95](https://github.com/v0lka/c0wrk/issues/95), fixed by [#113](https://github.com/v0lka/c0wrk/pull/113)) — a plain (non-goal) follow-up message that continued a failed non-terminal GOAL task silently degraded to a plain run: `tryContinueInterruptedTask` passed a nil goal state to `Resume`. It now loads the persisted goal state and re-enters the goal loop (with the same Model Profiles narrowing gate as the Resume button). Resuming a terminally **exhausted** goal now emits a visible notice ("the goal is over … continuing as a regular task") instead of silently continuing plain. See [goal-mode.md](./specs/domains/goal-mode.md#resume-continuity).
- **DeepSeek models: one-shot service calls no longer fail with HTTP 422** ([#109](https://github.com/v0lka/c0wrk/pull/109)) — the DeepSeek API splits thinking control across a `thinking` object whose `type` accepts only `enabled`/`disabled` and a separate top-level `reasoning_effort` field; passing the family's canonical effort spellings (`Off`/`High`/`Max`) through verbatim sent an invalid `thinking.type` and broke every one-shot service call on a DeepSeek model (session titles and commit messages pin the off tier). The sp4rk client — bumped `4d7c9a0` → `6ed15fa` for the fix — normalizes all spellings before the wire (`off`/`none` disable thinking, `low`/`minimal` map to effort `low`, `medium`/`xhigh`/`high` to `high`, `max` to `max`; unknown values fail closed to disabled), and c0wrk grows regression cases pinning the `serviceReasoningEffort` resolution for the title/commit tiers.
- **Embedded LLM: the hardware probe retries a transient `ETXTBSY`** ([#112](https://github.com/v0lka/c0wrk/pull/112)) — a probe may exec a freshly written artifact, and the kernel answers `execve` with `ETXTBSY` for as long as any process holds that file open for writing; every probe caller is fail-soft, so letting the momentary kernel hiccup through read as a definitive "tool did not answer" — for `ProbeDevices`, a machine with no accelerator at all. The spawn is now retried, only on `ETXTBSY`, within the existing probe timeout budget — the error is raised before the child runs, so a retry can never repeat a child's side effects. Also fixes `secondsToDuration` saturating in integer arithmetic: the float ceiling rounded `math.MaxInt64` up to 2^63 and the out-of-range conversion yielded a negative duration on amd64/Windows, defeating the clamp.

### Internal
- **Dependency bumps** — sp4rk is bumped `4d7c9a0` → `6ed15fa` for the DeepSeek reasoning-field normalization the one-shot service calls consume.
- **Test housekeeping** — `gittest.SuppressGitAutoMaintenance` injects `maintenance.auto=false` and `gc.auto=0` through git's environment config protocol so spawned git processes skip background maintenance: detached maintenance children outlived the command that spawned them and raced `t.TempDir` cleanup, causing flaky "directory not empty" failures on Linux CI; disposable test repositories never need background maintenance, and each affected `TestMain` opts out once. ## v0.9.1 — 2026-09-23

### Added
- **Commit hooks/signing gate (withhold-and-decide at the commit boundary)** — the hardened git baseline neutralizes hooks and signing on every invocation ([ADR-033](./specs/decisions/033-git-subprocess-hardening.md)), so committing in an untrusted repository silently landed an unhooked, unsigned commit, and the trust opt-out was unreachable from the workflow for hook-only or signing-only repositories (they scan clean at intake). The Commit RPC now runs exec-free `DetectCommitSuppression` (`core/workspace`) — commit-family hooks, the `core.hooksPath` redirect, and armed `commit.gpgsign` in repo and global config — and withholds an armed commit as a non-error Suppressed result instead of landing it stripped. The Git panel renders the decision as a dialog: **Trust & commit** records repository trust and re-runs the commit raw, so the repository's own hooks and signing execute; the force path commits through the hardened baseline (with a per-project "Don't ask again" skip flag that sends `force=true` directly the next time); a detection error fails the commit closed. `ScanGitConfig` reports the baseline-covered signing keys (`commit.gpgsign` truthy-gated, `gpg.format`, `gpg.program`, `user.signingkey`) so intake makes signing-armed repositories visible before the first commit, and the signing siblings stay inert — warning-free — when no config layer arms `commit.gpgsign`. - **Per-provider TLS verification override via SPKI pinning** — compatible providers (`llm.openai_compatible.<name>`, `llm.anthropic_compatible.<name>`) gain a `tls_fingerprint` key (`base64(StdEncoding, SHA-256(SubjectPublicKeyInfo DER))` — the RFC 7469 / Chromium pin-list construction) that replaces system-CA verification, so a self-signed or internal-PKI endpoint (vLLM, llama.cpp, LM Studio, an internal gateway) is reachable without abandoning peer authentication. The pin is the only switch: empty means normal verification, and there is deliberately **no accept-any-certificate state** — a wrong pin fails closed (`llmtls.ErrPinMismatch`, which carries the fact of the mismatch and nothing else), while a pin that cannot be base64-decoded to 32 bytes is logged as a Warn but still flows to the handshake. An effective HTTP proxy overrides the pin on every dial path, and `proxy.bypass_list` re-arms it per host: `DialPolicy{ProxyActive, TargetBypassed}` drives the two resolvers (`RouterEntryClient` for chat/inference, `DirectDialClient` for the Fetch Models listing and the lazy context-window probe), with `proxy.BypassMatcher` the single shared authority so the proxy and TLS bypass decisions cannot diverge; the pinned transport is derived once at construction, because a per-request `Clone()` would drop the keep-alive pool. The new `GetProviderTLSCertificate` RPC performs a credential-less handshake (https-only, no HTTP request, no API key) so the settings UI's "Get" button fills in whatever the endpoint presents right now; it is rejected, with an actionable error naming both remedies, only while the proxy dials for the target host, and a pointer sentinel (`*string`) at the API boundary keeps debounced partial saves from clearing a pin. Also fixes a pre-existing defect on these paths: the chatgpt/openai model-listing branches ignored the configured proxy. See [ADR-054](./specs/decisions/054-per-provider-tls-pinning.md).
- **flowsh shell analysis replaces the shipped default command blocklist** — the execute group's frozen 77-pattern default blacklist is deleted; `security.groups.execute.blocklist` is now a user-authored extension that is empty by default (a load-time migration carries a *customized* legacy `blacklist:` list into the new key, comparing the frozen old default order-insensitively so a merely reordered list is dropped; the Windows `Remove-Item` alias supplement is gone with it). The deterministic floor is now the blocklist + symlinks + the structural flowsh criteria C1–C8, computed once per shell call (`AttachShellAnalysis`) and consumed verbatim by the tool's Judge, the strict judge (via `StrictJudgeRequest.AnalysisContext`, behind an untrusted `shell_analysis` boundary), and the advisory Ask-Agent prompt; the criterion set supersedes the removed static unresolvable-token and PathsOutsideRoots judge stages. The canonical hard set grows by the five flowsh controls (exfil flow, privilege escalation, system write, destructive write outside the session roots, download cradle — never waivable by a strict ALLOW), while `command_unbounded_analysis` (the analyzer's ⊤ limitation) stays deliberately non-canonical and clearable, so `ExecuteUnattended` blocks only canonical hard reasons and a ⊤ verification command still runs. A failed analyzer or knowledge-base initialization now fails closed as the canonical `command_analysis_unavailable` reason instead of silently running with C1–C8 absent. See [ADR-052](./specs/decisions/052-flowsh-command-analysis.md).
- **Network-touching shell decisions are diagnosable and actionable** — an `autonomy_decision` for a `bash_exec`/`posh_exec` call now carries a `network` summary derived once in the registry's autonomy-decision funnel from the attached deterministic digest: `flow` (`cradle` — network→code-execution, **canonical**; `ingest` — network→filesystem, hard but **non-canonical**/judge-clearable; or `fetch` — a clean network read that neither executed nor persisted the content), `canonical`, `hosts` (resolved egress hosts, scheme/path/port stripped) and `operands` (files an ingest wrote). The card renders it as a dedicated Network line — a canonical cradle in the destructive tone, a judge-clearable ingest in the warning tone — so the two never read alike and a silent-mode operator can see WHICH flow was adjudicated and against which host instead of decoding a bare effect signature. Nil for non-network calls and step-limit gates; reloads identically via `reconstructContent`. See [`core/tools/network_decision.go`](./core/tools/network_decision.go), [event-catalog.md](./specs/contracts/event-catalog.md) and [security-model.md](./specs/architecture/security-model.md).
- **Autonomy axis (`security.autonomy_mode`: `standard` | `assisted` | `silent`) with an auditable receipt chain** — one enum replaces the former pair of boolean keys, the Smart Approve toggle and the silent-mode master switch (both survive only as legacy migration keys: honored at load — an explicit `autonomy_mode` wins, then `silent_mode.enabled: true` (silent), then `smart_approve: true` (assisted) — and dropped at the next save; an unknown value fails safe to `standard` with a load warning). **`assisted`** (the former Smart Approve): the strict OWASP ASI judge evaluates every escalated call through the unified confirmation funnel; a strict ALLOW executes without UI — except a canonical hard reason, which the deterministic backstop overrides to a confirmation card — and a strict DENY (`VerdictDeny`, a positive danger assessment) **terminates the call** with no card, carrying the judge's justification. **`silent`**: unattended operation — the `security.silent_mode` sub-policies (`tool_confirm`, `step_limit`, `ask_user`; live only in this mode) resolve the prompts without a human. The postures sit *inside* the confirmation funnel, after every deterministic gate, and never weaken one: `deny` groups are preserved and a hard safety reason is never auto-executed without the judge. In silent `tool_confirm.mode: judge` (the default) the strict judge holds **final authority over canonical hard reasons** — its ALLOW executes, canonical included, fully audited (ADR-053 D4; the assisted/standard paths keep the backstop, pinned by `TestSilentMode_JudgeTerminalCanonicalAllowExecutes`); `deny` mode is the judge-free hard floor. Every automatic decision emits a **persisted, non-blocking `autonomy_decision` session event** (`kind`, `mode`, `policy`, `verdict`, `tool`/`reason`, `justification`; rendered as a dedicated standard-format card and rebuilt identically on reload), so an unattended or auto-denying run's trajectory stays reconstructable (OWASP ASI10). The posture is **pinned per task**: it is set from Settings → Security (a 3-state Standard/Assisted/Silent control) and each task runs under the posture saved before it launched — a Settings save can never turn an already-started interactive task unattended mid-run, while a tightening reaches a live clone immediately. See [ADR-053](./specs/decisions/053-silent-mode.md).
- **`shell_exec` launch-shape override (argv template + declared-shell enum)** — the new `shell_exec` config section (`shell_exec.bash_exec` / `shell_exec.posh_exec` — only the platform-matching entry is live) lets the operator override HOW the platform shell tool launches the agent's command and declare WHICH shell the command text is written in. `command` is an **argv template** (first element = binary, exactly one element equal to the `{command}` placeholder, substituted at execution time as a single argv element — no string splicing or re-quoting); `shell` is a **closed enum** (`bash`/`sh`/`zsh`/`ksh`/`dash` and `powershell`/`pwsh`). The declared kind drives the tool **description** (an override rewrites only the "Purpose:" header to name the real launch command and shell; the default invocation keeps the legacy description byte-for-byte), the deterministic flowsh **analysis dialect** (`DeclaredShellKind` → `ShellAnalysisLangForTool`, so a `pwsh`-declared `bash_exec` analyzes PowerShell syntax as PowerShell), and the PowerShell UTF-8 bootstrap (applied only for the PowerShell family). Load is **fail-soft**: an invalid entry (empty/placeholder binary, no single standalone placeholder, unknown kind) emits a visible load warning and resets the section to the built-in launch shape; runtime updates reuse the blocklist's atomic re-registration path (validate → re-register → persist, rollback on failure). Everything else is untouched — process containment, `working_directory` validation, timeouts, the blocklist, the flowsh criteria C1–C9, and the confirmation funnel: the override changes *how* a command launches, never *what* is checked. The Settings card lives on the Security tab next to the execute-group blocklist editor. See [ADR-058](./specs/decisions/058-shell-execution-override.md).
- **Package-runner / bin-path resolution and the exec-scope criterion C10 (digest `sp4rk-shell-analysis/v4`)** — the flowsh binder (`bind/runner.go`, flowsh `v0.4.0`) now resolves package runners (`npx`/`bunx`) and `./node_modules/.bin/<bin>` paths onto the driven binary's own knowledge-base signature, so the everyday JS verification loop (`npx vitest run …`, `npx tsc -b`, `./node_modules/.bin/vitest …`) binds **deterministically with zero criteria** instead of escalating on the non-canonical C6 — closing the silent-mode audit's largest false-deny family. A **bounded** call whose Direct CodeExec/ProcSpawn effect targets a path **outside the session roots** fires the new hard **non-canonical** C10 `command_exec_outside_roots` (the exec sibling of C4/C9; keeps the audited TRUE_DENY `npx vitest run /tmp/…` denied without a judge coin-flip; the canonical set is unchanged). Winner selection is now **severity-first** (ties broken by the fixed priority order), so the hard C10 is never masked by the lower-numbered soft C9; the digest is bumped to `sp4rk-shell-analysis/v4` and the criteria renumbered **C1–C10**. See [ADR-061](./specs/decisions/061-package-runner-resolution-exec-scope.md).

### Security
- **Git subprocess hardening against untrusted repository config** ([ADR-033](./specs/decisions/033-git-subprocess-hardening.md)) — a repository is treated as attacker-controlled data: a hostile `.git/config` can make git execute hooks, filters, fsmonitor daemons, merge drivers, and editors during ordinary (even read-only) operations. Four cooperating layers: a global baseline on every git process (fsmonitor off, an empty safe `core.hooksPath`, `commit.gpgsign=false`, `GIT_EDITOR=true`); per-repo neutralization that re-scans the discovered config fresh on every invocation and fails closed when it cannot be scanned; intake detection emitting `project:git_config_risk` as a dismissable warning on project switch and work-directory add; and an agent-side write gate (`git_internal_path` as a canonical hard judge reason) that always confirms mutating file tools targeting a workspace `.git` tree. A review pass closed the remaining gaps: transport keys reachable from remote operations (`core.sshCommand`, `core.askPass`, credential helpers, `core.gitProxy`), external diff drivers (`--no-ext-diff`), `core.worktree` redirects, attribute-routing sources `attr.tree` cannot cover, linked-worktree common config, SHA-256 repos, include-bearing configs on git < 2.45 (fail closed), a Stat-to-Open TOCTOU, and `GIT_ATTR_*` environment stripping — while narrowing the `attr.tree` kill so CRLF-normalized repositories no longer report falsely-modified files. Hooks and filters, including legitimate git-lfs, never run inside c0wrk unless the repository is explicitly trusted.
- **Trusted git repositories with snapshot-bound trust** ([ADR-034](./specs/decisions/034-git-trust-opt-out.md)) — `security.trusted_git_repos` records repository roots the user explicitly trusted (via the warning toast's "Trust this repo" action, which also offers "Ignore" and an agent-task "Fix", or via Settings → Security → Trusted repos). Trusting a repository opts it back into its own git configuration — hooks, filters, and signing run as they would outside c0wrk — but the trust is bound to a fingerprint of the scanned config: any drift evicts the trust, re-hardens the repository, and re-warns with a reason and a diff. `security.harden_git_repos` is the mutually exclusive inverse for roots that must always be hardened.
- **Validated command-substitution exception** ([ADR-038](./specs/decisions/038-validated-command-substitution.md)) — the safety judge now promotes a pure `VAR=$(...)` assignment whose inner command is fully assessable to assessable, ending a class of false-positive confirmations. Bare argument-position substitutions, unbound references such as `$HOME`, and any name poisoned by a literal or non-assessable binding stay suspicious via a fail-closed union over all bindings; bash and PowerShell parity rules are documented, with regression tests driving the real judge.
- **Reproducible CI dependency installs** — `frontend/package-lock.json` is committed (previously gitignored), CI and release workflows switched to `npm ci` on Node 24 with lockfile-keyed caching, ending flaky live resolution of floating ranges.

### Internal
- Go toolchain bumped to 1.27.1 (`go.mod` and CI pins in lockstep), with several sp4rk SDK bumps across the cycle (notably: delegation-spec persistence, per-strategy compaction predictions, fixed-shape persistent session defaults, and the six-label tool-description rubric).
- Small-LLM: the `max_tools` budget and semantic router tool matching are removed in favor of a static union of always-present pins, protected tools, MCP tools, and turn-scoped guarantees — `SelectTools` no longer trims or matches ([ADR-035](./specs/decisions/035-remove-small-llm-tool-budget.md)); requested `#subagents` keep the `delegate` tool under narrowing, and the lite system prompt retains essential operational guidance.
- Subagent Profiles gain a `skills:` frontmatter list: required skills resolve fail-closed against the skill catalog, are activated for the delegated subagent, and are inherited on redelegation ([ADR-037](./specs/decisions/037-agent-profile-skills.md)).
- Tests: Windows-compatible temp-dir/handle cleanup ordering and a cross-platform unreadable-file helper; startup tests use explicit benchmarks instead of timing budgets; tool-description tests enforce all six rubric labels per line; an integration test pins the sound-listener coverage invariant across CHAT↔CODE toggles.
- CI: Windows jobs disable HTTP/2 for Go module downloads to dodge intermittent proxy.golang.org stream resets.
- New specs: [ui-scale](./specs/domains/frontend/ui-scale.md), [sound-notifications](./specs/domains/frontend/sound-notifications.md), [git-auto-fetch](./specs/domains/git-auto-fetch.md), and ADRs 033–038.
