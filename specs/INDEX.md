# Specs Index

> **Engine behavior is canonical in sp4rk.** c0wrk's `specs/` cover c0wrk-only wiring (layering, lifecycle, session roots, the policy-enforcing registry wrapper, conductor/delegation tools, persistence, frontend). Engine primitives (Executor, Router, Planner, Reflector, Conductor, Blackboard, Tool/ToolRegistry, LLM Router, compaction, MCP gateway) are documented in [the sp4rk spec set](https://github.com/v0lka/sp4rk/blob/main/specs/INDEX.md) in the sp4rk repository. Engine-related c0wrk specs below cross-reference their canonical sp4rk counterparts.

## Domain Dependency Graph

```
                ┌──────────┐
                │ frontend │
                └────┬─────┘
                     │ Wails events + RPC
                     ▼
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌───────┐
│ desktop  │───▶│ backend  │───▶│   core   │───▶│ sp4rk │
└──────────┘    └────┬─────┘    └──────────┘    └───────┘
                     │ direct import               ▲
                     ▼                             │
                   ┌───────┐                       │ separate repository
                   │ sp4rk │  github.com/v0lka/sp4rk (external module)
                   └───┬───┘───────────────────────┘
                       │ require github.com/v0lka/sp4rk (no replace)
```

Import rule: each arrow is one-way. `backend` imports `core` AND sp4rk directly (per ADR-008). `core` remains the primary sp4rk consumer. sp4rk is a separate Go module (`github.com/v0lka/sp4rk`) living in its [own repository](https://github.com/v0lka/sp4rk) (per ADR-015); the root module depends on it as a normal external dependency (`require github.com/v0lka/sp4rk`, no `replace` directive).

- [063-mcp-tool-timeouts.md](decisions/063-mcp-tool-timeouts.md) - MCP tool timeouts: per-server `timeout` (bounds the `initialize` + `tools/list` handshake and is the default per-call bound) and optional `call_timeout` (per-call override, inherits `timeout` when unset) bound every MCP operation at the **sp4rk gateway layer** via `context.WithTimeoutCause`; `client.Start` is deliberately never wrapped (a slow handshake must not kill the stdio child process); a single 60s default (`defaultMCPTimeout`); **3 consecutive** genuine `tools/call` timeouts flag `ServerStatus.Unhealthy` (marked, never killed — a clean call clears it); caller cancellation is never misattributed (via `timeoutErrorFor`); a typed `*TimeoutError` (unwraps to `context.DeadlineExceeded`) surfaces to the agent loop; c0wrk wires `mcp.servers.<name>.{timeout,call_timeout}` fail-soft to the default (invalid values rejected at the UI save path)
- [064-branch-scoped-lazy-vector-index-open.md](decisions/064-branch-scoped-lazy-vector-index-open.md) - Branch-scoped lazy vector-index open: every git branch gets its own **stable** chromem DB root (`<project>/vector_index/branches/<collectionName(branch)>/`, keyed by the same sanitized identity as the branch sidecar), so `Service.SetProject` no longer opens the persistent DB — it only prepares the layout and runs the one-time legacy migration (stray root-level `<hash2hex>` collection dirs are renamed into their branch root, name recovered from the collection's chromem metadata and accepted only in `collectionName`'s exact shape, otherwise parked under `branches/_orphan/`) — and `Service.SwitchBranch` decodes **only the active branch** after releasing the outgoing branch's residents (`releaseBranchResidentsLocked`, so a switch peaks at one working set and a failed open fails closed instead of serving the previous branch). Removes the `O(branches × documents)` startup stall (74 s and growing in the field, minutes on a large index, all of it under the service write lock); the pre-open status becomes an honest `{state: "loading", phase: "open"}` (no progress fraction, rendered "Preparing index…", reindex action busy) instead of a fake `{state: "indexing", phase: "both"}` 0/0 bar. Rejected: prune/TTL-cap the branch collections, per-branch single-file snapshot (`Export`/`Import` — ADR-049 option G), status-only fix, parallelizing chromem's decode, replacing the store (sqlite-vec / usearch / mmap)
