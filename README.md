# c0wrk

Локальный AI-ассистент для разработки: desktop-приложение (Wails + Go), которое помогает исследовать кодовую базу, выполнять задачи по шагам и работать с инструментами через единый интерфейс.

> Статус: активная разработка. Некоторые сценарии и UX-потоки ещё дорабатываются (см. [Roadmap и ограничения](#roadmap-и-ограничения)).

## Ключевая ценность

- **Один рабочий контур для AI-задач**: планирование, пошаговое выполнение и инструменты в одном приложении.
- **Локальный запуск**: удобно для приватных репозиториев и контроля окружения.
- **Гибкая LLM-интеграция**: проект содержит SDK-слой провайдеров и унификацию сообщений/инструментов.
- **Фокус на инженерный workflow**: исследование кода, изменения, проверка результатов.

## Возможности

- Desktop UI на базе **Wails** (`main.go`, `frontend/`, `desktop/`).
- Ядро оркестрации задач и исполнения шагов (`core/`).
- Интеграции с LLM-провайдерами и конвертацией сообщений (`sdk/llm/`).
- Поддержка tool-based workflow для анализа и модификации проекта.
- Тесты для ключевых частей (см. раздел [Тесты](#тесты)).

## Требования

- **Go 1.26+** (в `go.mod`: `go 1.26.1`)
- **Node.js** и npm (для frontend/Wails)
- **Wails CLI v2**

Установка Wails CLI:

```bash
go install github.com/wailsapp/wails/v2/cmd/wails@latest
```

Проверьте, что бинарь доступен в `PATH`:

```bash
wails doctor
```

## Установка

```bash
git clone <your-fork-or-repo-url> c0wrk
cd c0wrk
go mod download
```

Frontend-зависимости (если требуется локально):

```bash
cd frontend
npm install
cd ..
```

## Быстрый старт

### 1) Режим разработки (рекомендуется)

```bash
wails dev
```

Это поднимает desktop-приложение с hot-reload фронтенда.

### 2) Сборка desktop-приложения

```bash
wails build
```

### 3) Запуск с открытым инспектором

В `main.go` включён флаг:

- `C0WRK_DEBUG=1` → открыть DevTools при старте

Пример:

```bash
C0WRK_DEBUG=1 wails dev
```

## Конфигурация

На текущем этапе проект использует переменные окружения и настройки провайдеров в коде/конфигах соответствующих модулей.

Минимально подтверждённая переменная:

- `C0WRK_DEBUG` — включает инспектор Wails на старте.

Для LLM-провайдеров обычно требуются API-ключи (формат зависит от выбранного провайдера и реализации в `sdk/llm`). Рекомендуется хранить их в локальном `.env`/секрет-хранилище и не коммитить в репозиторий.

## Примеры использования

Типовой сценарий нового разработчика:

1. Запустить `wails dev`.
2. Открыть проект/репозиторий в интерфейсе.
3. Сформулировать задачу (например, анализ модуля или подготовка изменений).
4. Выполнить шаги плана и проверить результат через встроенные инструменты.

Пример запуска в debug-режиме:

```bash
C0WRK_DEBUG=1 wails dev
```

## Структура проекта

```text
c0wrk/
├─ main.go            # точка входа desktop-приложения (Wails)
├─ core/              # планирование, исполнение шагов, логика workflow
├─ desktop/           # Wails-адаптеры и app lifecycle
├─ sdk/
│  └─ llm/            # провайдеры LLM, конвертация сообщений, тесты
├─ frontend/          # UI (web-часть Wails-приложения)
├─ go.mod             # Go-модуль и зависимости
└─ TODO.md            # backlog/направления развития
```

## Разработка

### Полезные команды

```bash
# скачать Go-зависимости

# запустить приложение в dev-режиме
wails dev

wails build
```


```bash
go test ./sdk/llm -v
```
